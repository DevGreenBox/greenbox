# Дизайн-система «Стандарт категории»

Этап 4 плана, актуализировано 30.09.2026 по итоговому коду (этапы 0–6 закрыты, финальное ревью — ship). Направление выбрано заказчиком по живому прототипу (`prototype/variants/standart/`), контракт — `.impeccable/surfaces/site-src-app-page-tsx.md`. Здесь система, перенесённая в сайт Next.js: токены, сетка, шкала, сцены, движение, компоненты и правила для агентов секций.

Живое превью всех компонентов во всех сценах: `/ds` (только dev-сервер, в продакшене 404, `noindex`, в sitemap нет).

## 1. Главное за минуту

- **Поля по бокам:** 20 / 40 / 64 / **100 px** (от 1280 и шире — ровно 100 px на любой ширине). У контейнера нет `max-width`: контент тянется между полями, ограничивается только мера текста (60–72ch) и отдельные медиа.
- **Сцены:** три — `light`, `light-2`, `dark`. Каждая переопределяет токены текста, линий и поверхностей, поэтому компонент выглядит верно на любом фоне без правок.
- **Тёмная тема:** базовые сцены `#12121F` (и `#1A1A2E`), акцентные глубже — `#0A0A14`. Секций и панелей на сплошной зелёной заливке нет: панели офферов в «Почему» тёмные, зелёные в них только кнопки (30.09.2026).
- **Шкала:** заголовки Martian Grotesk — h1–h2 широкий инстанс (ширина 115, вес 650), h3–h4 обычной ширины (600); h1 40 → 75 px (потолок 96 px), h2 30 → 51, h3 22 → 27, h4 18 → 20. Текст Onest 16/1.5, лид 17 → 19. Подписи «инспектора» — Martian Mono.
- **Ритм:** отступ секции 72 px на 390, 144 на 1440, потолок 160. Заголовок → содержимое 40 → 72.
- **Движение:** шаблонного всплытия блоков нет, контент стоит на месте; движутся только авторские моменты (§7). Одна кривая `cubic-bezier(0.16, 1, 0.3, 1)`, длительности — токены `--dur-hover` 250 / `--dur-move` 400 / `--dur-reveal` 600 / `--dur-enter` 700 / `--dur-draw` 1300 ms. Без JS и при reduced-motion всё видно сразу.
- **Контраст:** 84 пары токенов (14 × 3 сцены × 2 темы) проверены в браузере — все проходят AA (раздел 3.2).

### 3.4 Утилиты Tailwind

Стандартные цвета, кегли, шрифты, тени и кривые Tailwind отключены: `text-gray-500` или `text-2xl` не соберутся. Доступно:

| Утилита | Токен |
|---|---|
| `bg-scene`, `bg-surface`, `bg-surface-hover`, `bg-inset` | фон сцены, поверхность, подложка |
| `text-ink`, `text-ink-2`, `text-ink-3` | текст, второй, третий (крупный) |
| `bg-accent`, `bg-accent-hover`, `text-on-accent` | акцентная заливка и подпись на ней |
| `text-accent-ink`, `bg-accent-tint` | зелёный текст и иконки, зелёная подложка иконки |
| `border-line`, `border-line-strong`, `border-line-control` | линии |
| `text-error`, `outline-focus` | ошибка, фокус |
| `font-sans` (Onest), `font-display` (Martian Grotesk 600, h3–h4), `font-wide` (Martian Grotesk wdth 115 / 650, h1–h2) | гарнитуры; `Heading` выбирает сам |
| `text-h1` … `text-h4`, `text-lead`, `text-body`, `text-small`, `text-caption` | шкала (кегль + интерлиньяж + трекинг + начертание) |
| `rounded-panel`, `rounded-card`, `shadow-soft`, `shadow-lift`, `shadow-float` | поверхности |
| `ease-out` (наша кривая), `transition` (250 ms по умолчанию) | движение |
| `mt-(--space-head)`, `py-(--section-y)`, `gap-(--gap)`, `max-w-(--measure)` | любые токены через `(--имя)` |

Вариант `dark:` означает **тему**, а не сцену (явный выбор или система без JS). Для цвета он почти не нужен: токены сцены уже учитывают тему.

## 4. Сетка и ритм

| Ширина | Поле слева и справа | Колонки: `--gap` | Сплит: `--gap-lg` |
|---|---|---|---|
| до 639 px | 20 px | 16 → 18 | 32 → 39 |
| 640–1023 px | 40 px | 18 → 22 | 39 → 51 |
| 1024–1279 px | 64 px | 22 → 25 | 51 → 58 |
| 1280 px и шире | **100 px на любой ширине** | 25 → 28 | 58 → 64 |

- **Контейнер** (`Container`, класс `.wrap`): `width: 100%`, `padding-inline: var(--gutter)`, без `max-width` и центрирования — решение заказчика. Проверено на 1280, 1440, 1920 и 2560: левый край логотипа и заголовков — 100 px, правый край кнопки шапки — 100 px (`margins-*.png`).
- **Колонки** задаются под блок сеткой Tailwind (`grid lg:grid-cols-2 gap-(--gap-lg)`), общей 12-колоночной сетки нет, как и у референсов.
- **Мера текста:** абзацы и лиды — `max-w-(--measure)` (68ch) или уже; заголовки держит `text-wrap: balance`.
- **Вертикальный ритм:**

| Токен | 390 px | 1440 px | Потолок | Что |
|---|---|---|---|---|
| `--section-y` | 72 | 144 | 160 (от 1673) | отступ секции сверху и снизу (класс `.section`) |
| `--space-head` | 40 | 72 | 72 | заголовок секции → её содержимое |
| `--space-lead` | 20 | 27 | 28 | заголовок → лид |

  Над заголовком воздуха больше, чем под ним: 144 сверху против 72 до содержимого. Внутри карточки — 8–16 px (`gap-2` … `gap-4`).
- **Шапка:** `--header-h` 64 px (мобильный) / 80 px (от 1024), после прокрутки `--header-h-compact` 64 / 68 px. По `--header-h-compact` отступают якоря (`scroll-padding-top`).

- Трекинг не ниже −0.04em. Капс не используем (широкий Martian и так крупный).
- **Шрифты** (`src/lib/fonts.ts`, `src/app/fonts/`, лицензии OFL 1.1 рядом): срезы по символам (ASCII, русский, знаки набора), Martian — статичные инстансы, всего 55 КБ против прежних 101 (Unbounded + Onest + JetBrains Mono). Unbounded заказчик отклонил как «типовую студию», Geist — как дефолт create-next-app.
- **Стратегия поздних шрифтов** (`layout.tsx`, `lateFontsCss`): предзагрузка только у Onest и широкого Martian (h1 первого экрана). Обычный Martian (h3–h4) и Martian Mono с `preload: false`; с JS они включаются после `load` и двух кадров (класс `late-fonts` на `<html>`, до этого — запасные шрифты). Иначе браузер находит их в первой раскладке и качает до отрисовки наравне со шрифтами LCP (+150 мс к мобильному LCP). `display: swap`, запасной Arial с `size-adjust`. Цена — один пересчёт стилей после `load`. Без JS правило не действует.
- `text-wrap: balance` у заголовков, `pretty` у абзацев, `overflow-wrap: break-word` у заголовков — длинное слово на 320 px не вылезет за экран.
- Абзац кеглем заголовка (текст офферов «Почему», крупная цитата отзыва) — интерлиньяж не ниже 1.35: это многострочный текст, а не заголовок (`leading-[1.35]`).
- **Двухтоновый заголовок** (как у Uncap, Makro, AGIMA): утверждение + серое продолжение `<span className="text-ink-3">…</span>`. Только в h1–h2: `--text-3` годится лишь для крупного текста.
- **Табличные цифры:** у Onest они есть (`tabular-nums`) — номера заказов, реквизиты, сроки, прогресс «Шаг 2 из 5».
- **Русский набор:** тексты из `src/content` выводятся через `typograf()` — тире не начинает строку, «в», «и», «за» не висят в конце строки, «2–2,5 недели», «1 000» и «№ 1043» не рвутся.
- **Градиентный текст** — один на сайт: слово «Интернет-магазины» в первом экране, класс `.text-gradient-hero` (с запасным цветом для режима высокой контрастности и выделения).

## 6. Сцены

**Как устроено.** Любой элемент с `data-scene="light | light-2 | dark"` становится сценой: красит фон и текст и переопределяет все цветовые токены. Компоненты внутри берут токены ближайшей сцены, поэтому кнопка, поле или чип одинаково корректны на светлом, тёмном и зелёном фоне. Сцены вкладываются: тёмная панель внутри светлой секции — `<div data-scene="dark" className="rounded-panel">`.

**Тема** — атрибут `html[data-theme]` (ставит скрипт в `layout.tsx` до отрисовки: сохранённый выбор или система). Без JS атрибута нет, и тему даёт `prefers-color-scheme` — те же значения через вариант `dark`.

Почему так:
- Тёмное начало и тёмный конец, как у Newthink и AGIMA: первый экран и финал — контрастные сцены (вывод 10 разбора референсов). Холст страницы тоже `#0A0A14`: «оттяжка» прокрутки на телефоне не мигает светлым.
- Кейсы на тёмном: скриншоты сайтов (в основном светлые) читаются крупным визуалом, как у Makro.
- Зелёной заливки на всю секцию нет — «Почему» тёмная в обеих темах, сцены `green` в системе больше нет (правка 29.09.2026): в тёмной теме «Почему» было сплошь `#00E676` — 69 % кадра 1440 × 900 зелёные. Теперь секция тёмная в обеих темах, зелёные только две панели офферов — 21 % кадра. Сцены `green` в системе больше нет. Соседи в тёмной теме всё равно различаются: Команда `#1A1A2E` → Почему `#0A0A14` → Вопросы `#12121F`.
- Пары «светлая → светлая-2» (Квиз → Процесс, Отзывы → Команда) различаются тоном и в тёмной теме (`#12121F` → `#1A1A2E`).

**Переход к секции по якорю** (шапка, меню, подвал, кнопки, адрес с #; заказчик 01.10.2026): блок встаёт по центру видимой области под шапкой — поровну места сверху и снизу. Переход делает браузер (плавная прокрутка, фокус, история — родные), `layout/AnchorCenter.tsx` только считает секциям главной `scroll-margin-top`: по центру — содержимое без полей секции; не помещается (телефон, 1280 × 800) — верх содержимого под шапкой с зазором 24 px; закреплённые кейсы — свой отступ из CSS (сцена во весь экран). Пересчёт при смене размеров секций и окна; открыли главную с якорем — после прокрутки браузера встаёт заново.

**Шапка:** всегда тёмная сцена — читается над любой секцией. Над первым экраном у самого верха прозрачна (`<Header overlay />`), после 48 px прокрутки плотная `#0A0A14` с линией снизу и высотой 68 px. Без JS — сразу плотная. **Токены.** Кривая одна — `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)` (экспоненциальное замедление, во всех `transition` и `animation`; `linear` — только у вращения спиннера и у прокрутки, привязанной к скроллу). Длительности — по роли:

| Токен | Значение | Что |
|---|---|---|
| `--dur-hover` | 250 ms | цвет, рамка, подложка; `transition` Tailwind по умолчанию |

Своё у «инспектора» только расписание: выделение держится 1.4 s на блоке и переходит дальше (задержки 1.5 → 2.9 → 4.3 s).

**`Reveal`** (`src/motion/Reveal.tsx`, смонтирован в `page.tsx`) — только для авторских появлений. Элементу с атрибутом `data-reveal` он ставит `data-revealed`, когда тот входит в экран, и номер в пачке `--i` (каскад); на `<html>` — класс `reveal-on`. Исходное (спрятанное) состояние и переходы описывает CSS-модуль секции под `.reveal-on` и `@media (prefers-reduced-motion: no-preference)`, как в `Get.module.css` и `Process.module.css`. Общих вариантов появления (подъём, проявление, шторка) больше нет.

- Не прячьте контент: анимируется графика секции (линии, маркеры), а не текст.
- `Reveal` видит элементы, которые есть в DOM при монтировании. Для динамического содержимого (шаги квиза) — свои переходы.
- Новое движение секции — только авторское и одно на секцию (раздел 1 разбора: «одно сильное движение, остальное тихо»).

**GSAP — `useScrollTrigger`** (`src/motion/useScrollTrigger.ts`), для закреплённой горизонтальной прокрутки кейсов:

```tsx
'use client'
const ref = useRef<HTMLDivElement>(null)
useScrollTrigger(ref, ({ gsap }) => {
  const track = ref.current!.querySelector<HTMLElement>('[data-track]')!
  const distance = () => track.scrollWidth - innerWidth
  gsap.to(track, {
    x: () => -distance(),
    ease: 'none',
    scrollTrigger: { trigger: ref.current, pin: true, scrub: 1, end: () => `+=${distance()}`, invalidateOnRefresh: true },
  })
})
```

- GSAP и ScrollTrigger грузятся отдельным чанком только когда совпало условие (по умолчанию `DESKTOP_MOTION`: от 1024 px и движение разрешено). На телефоне и при reduced-motion библиотека не грузится вовсе.
- Всё созданное в `setup` откатывается само при смене условия и при размонтировании. Вернуть функцию из `setup` — для своей уборки.
- Базовая раскладка (без JS, мобильная, reduced-motion) — обычная CSS-сетка или лента, GSAP только добавляет закрепление поверх.
- Закрепляйте обёртку, которую React не перерисовывает (ScrollTrigger оборачивает её в `pin-spacer`).

**Reduced-motion и без JS.** Три режима, и во всех контент виден сразу:
- без JS: `data-reveal` ничего не прячет (прячет только класс `reveal-on`, его ставит `Reveal`), шапка плотная, переключатель темы и бургер скрыты, формы — обычные POST-формы;
- `prefers-reduced-motion: reduce`: `Reveal` ничего не делает, все анимации и переходы — 0.01 ms (base.css), плавная прокрутка якорей выключена, высота квиза не анимируется, смена темы без View Transitions, GSAP не грузится;
- полное движение — всё выше.

### Горизонтальные ленты и липкие сцены (по опыту секции «Кейсы», 29.09.2026)

- **ScrollTrigger создаётся только после остановки прокрутки** (`whenScrollIdle` в `motion/useScrollTrigger.ts`, 01.10.2026). Его первый `refresh()` прокручивает страницу в 0 и обратно и этим обрывает плавный переход к якорю: GSAP грузится как раз на пути вниз, и «Обсудить проект» с первого экрана застревал в кейсах, не доехав до формы (то же «Отзывы», «Вопросы»).

- Закреплённая горизонтальная лента делается через CSS `position: sticky` + `scrub` в ScrollTrigger (`useScrollTrigger`), а не через `pin: true`. Высоту секции CSS считает до загрузки GSAP, поэтому якоря ниже не прыгают.
- Контейнеру с горизонтальной прокруткой нужен `position: relative`, иначе элементы `.sr-only` внутри раздувают страницу вбок.
- Внутри липкой сцены не ставьте `data-reveal`: элементы появлялись бы в момент, когда сцена уже закреплена, и мигали.

### Первая загрузка: что попадает в JS

Мобильный Lighthouse считал LCP 3,4 с при ~170 КБ JS (правка по чеклисту, пункт 8, 29.09.2026). Теперь в JS первой загрузки только каркас Next/React и мелкое поведение (~3 КБ gzip своего кода), всего 149 КБ:

- **Классы для замеров** (`GridLive`) приходят с сервера строками — карты CSS-модулей в клиентский JS не идут.
